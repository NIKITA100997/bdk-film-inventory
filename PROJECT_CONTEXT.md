## 1. Общие сведения и назначение системы

**Проект:** Комплексная система производственного, складского и оперативного учёта для **Белорусского дверного комбината (БДК)**.
- **Главная цель:** Сквозной партионный учёт материалов (рулоны плёнки, штрипсы, кромка, МДФ, брус), полуфабрикатов (стоевые, поперечные, филёнки, щиты, заготовки) и готовой продукции; планирование загрузки участков, диспетчеризация цеха, формирование сменных нарядов с QR-кодами, списание сырья по FIFO и контроль брака/перерасхода.

### Производственная география и специфика:
- **Площадка «Северный»:** Основной склад сырья и плёнки, форматно-раскроечные станки, нарезка штрипсов, вакуумные прессы, окутка погонажа и царговых элементов.
- **Площадка «Фабрика»:** Участок щитовых дверей, доборный погонаж, сборка каркасов, прессы горячей склейки, фрезеровка и шлифовка МДФ, кромкооблицовка, упаковка.
- **Особенность перемещений:** Сырьё и полуфабрикаты нарезаются/готовятся на Северном и партиями перемещаются на Фабрику. На Фабрике нет отдельного начальника склада, поэтому учёт должен быть максимально быстрым и дружелюбным к мастерам участков (планшеты, сканирование QR).

### Технологический стек:
- **Backend:** Python 3.12+ / FastAPI / SQLAlchemy / Alembic / PostgreSQL / Uvicorn.
- **Frontend:** React 19 / TypeScript / Vite / Ant Design (antd v6) / TanStack Query (v5).
- **Печать и сканирование:** Векторные SVG QR-коды, библиотека `html5-qrcode` для камер планшетов/смартфонов, термопечать этикеток (Codex G500 / PDF) и листы формата А4 landscape для сменных нарядов.
- **Интеграции:** Выгрузки счетов и спецификаций из 1С:Предприятие, вебхуки и лиды из Bitrix24.

4. **Деплой:** Никаких пушей в ветку `master` и никакого деплоя без прямой команды пользователя («выкладывай», «заливай», «да» либо согласованного времени выкладки).

6. **Очистка данных:** Временные тестовые данные, QA-скрипты и файлы после проверки обязательно удалять. Временные скрипты для чтения на проде называть с префиксом `_ro_*`.
7. **Зоны без изменений:** Царговые двери и классический погонаж не изменять без явного указания. Конфигурацию безопасности сервера пока не трогать.

## 3. Градация сущностей системы (Устранение путаницы)

В системе выстроена четкая 4-уровневая иерархия:

```
[Заказ клиента / Счёт 1C / Bitrix24] 
                 │
                 ▼
     [Заказ на производство (ProductionOrder)]
                 │
                 ▼
       [Задание на участок (ProductionTask)]  ──► QR-код "TASK:<id>"
                 │
                 ▼
         [Строка задания (ProductionTaskLine)]
```

1. **Заказ клиента (CustomerOrder / Deal):**
   - Коммерческий документ от отдела продаж.
   - Содержит номер счёта 1С, дату отгрузки покупателю, контрагента, список готовой продукции (например, 20 дверей «Модель 01», цвет «Дуб сонома»).
   - Менеджер по продажам работает только на этом уровне, не вмешиваясь в технологические этапы цеха.

2. **Заказ на производство (ProductionOrder):**
   - Запуск партии в производство (формируется диспетчером/начальником производства).
   - Объединяет один или несколько заказов клиентов либо запускается «на склад».
   - Имеет статусы: `draft` (черновик), `released` (запущен в работу), `completed` (завершен), `closed` (закрыт).
   - При запуске формирует спецификацию потребности сырья, резервирует плёнку и генерирует технологическую цепочку заданий по участкам.

3. **Задание на участок / цеховое задание (ProductionTask):**
   - Конкретная работа для одного участка/станка (например, *«Фрезеровка МДФ Фабрика»*, *«Окутка Северный»*, *«Сборка каркаса»*, *«Пресс склейки»*).
   - Именно на этом уровне формируется **сменный наряд-задание** и генерируется QR-код вида `TASK:<id>`.
   - Имеет плановые даты начала/окончания, статус (`pending`, `in_progress`, `completed`), привязку к мастеру и станку.

4. **Строка задания (ProductionTaskLine):**
   - Подетальный технологический элемент внутри наряда (наименование заготовки, размеры $H \times W \times T$, цвет, программа ЧПУ, количество плановое и сделанное годное/брак).

## 4. Хроника и контекст текущего диалога

### 4.1. Умное списание штрипсов на доборном погонаже (Пул FIFO)
- **Контекст проблемы:** На Фабрике изготавливается доборный погонаж. Ранее требовалось перемещать конкретные рулоны/штрипсы и мастеру отчитываться по каждому номеру индивидуально. Из-за отсутствия постоянного кладовщика на площадке это вызывало простои и задержки отчётов.
- **Принятое решение:**
  1. На Северном нарезаются штрипсы и отправляются перемещением на Фабрику.
  2. Для участка Фабрики важен только **цвет и точная ширина** (допуски нарезаются на Северном сразу в размер).
  3. Мастер берёт любой физический штрипс с поддона, а система списывает метраж по алгоритму **FIFO из пула штрипсов** соответствующего цвета и ширины.
  4. Если физически штрипса не хватило, разрешено проведение отчёта с фиксацией **минусового остатка (овердрафта)** по заданию с последующей подпиткой или локальной экспресс-инвентаризацией.

### 4.3. Кардинальная переработка Монитора производства и планшетного UX

  - Добавлен компактный горизонтальный скролл-контейнер с расчётом высоты под экран планшета.
- **Монитор производства (`ProductionMonitor.tsx`):**
  - Стал полноценным **главным рабочим местом начальника производства**.
  - Объединён с заказами цеха: добавлена вкладка «Заказы в цехе», быстрый запуск нарядов, пакетная печать заданий прямо из верхнего тулбара без необходимости переходить в разделы продажников.
  - Разъяснён показатель **«Готово к склейке»**: отражает комплектность полуфабрикатов (каркасы + обе панели МДФ), готовых для подачи на пресс горячей склейки щитовых полотен.
- **Быстрый отчёт (`BatchQuickReport.tsx`):**

- **Ламинация (`PrepView.tsx`):**

### 4.5. Расследование и восстановление QR-кодов в печатных формах
- **Суть проблемы:** Пользователь заметил, что при открытии задания цеха QR-код был, а при печати с общего вида монитора QR-код «пропал».
- **Причина:** В системе исторически было две формы: индивидуальный «Наряд на станок» (`printJobCard.ts` — где QR-код был всегда) и пакетная печать по участкам (`printTasks.ts` — где была только таблица без QR-кода). Кнопка в мониторе вызывала именно пакетную печать.
- **Решение:**
  1. Разработан модуль [`frontend/src/utils/qrSvg.ts`](file:///c:/Users/User/Downloads/Учет%20пленок/frontend/src/utils/qrSvg.ts) — чистый векторный генератор QR в SVG без Canvas, без задержек и без сетевых запросов.
  2. Во все печатные формы [`frontend/src/utils/printTasks.ts`](file:///c:/Users/User/Downloads/Учет%20пленок/frontend/src/utils/printTasks.ts) (панели МДФ, группы операций, детальные списки) в правый верхний угол встроен блок с QR-кодом `TASK:<id>` (или группой QR при нескольких заданиях на листе).
  3. В `printJobCard.ts` добавлен SVG-fallback. Теперь мастер может мгновенно отсканировать любой наряд планшетом или телефоном.

   - Закрепление интерфейса:
     - Начальник производства — монитор производства, планирование, контроль сроков и печать.
     - Мастер участка — планшетный экран выполнения заданий, скан QR, быстрый отчёт годное/брак.
     - Менеджер по продажам — реестр заказов клиентов, контроль готовности, без доступа к изменению цеховых нарядов.
4. **Тонкая настройка печатных форм под специфику участков:**
   - Фрезеровка МДФ: обязательный вывод имени программы ЧПУ и фрезы.
   - Кромка: толщина (ABS 2 мм / ПЭТ 1 мм / алюминий), цвет и количество сторон.
   - Сборка каркаса: вывод карты раскроя пенопласта и бруса.

   - Комплексная приёмка функционала пользователем на dev-сервере.
   - Выкатка ветки `shchitovye-progon` на боевой сервер `100.94.188.5`.
